# Передача входных данных

Инструмент поддерживает два канала приёма данных от заказчика. Выбирается ровно один канал на сессию — тот, который удобнее клинике.

## Канал 1. Ссылка на облачное хранилище

### Когда использовать

- Данные хранятся в облаке клиники (Google Drive, Dropbox, корпоративный S3)
- Файл обновляется регулярно и всегда лежит по одному адресу
- Размер файла большой (> 100 МБ), пересылать через мессенджер неудобно

### Как заполнить

Открыть `config/settings.env` и заполнить строку `DATASET_URL`:

```
DATASET_URL=https://drive.google.com/file/d/1abc.../view
```

### Поддерживаемые URL

**Google Drive.** Обычная share-ссылка вида `https://drive.google.com/file/d/FILE_ID/view` или `https://drive.google.com/open?id=FILE_ID`. Файл должен быть открыт для чтения по ссылке (Sharing → Anyone with the link). Агент автоматически преобразует URL в прямую ссылку скачивания.

**Dropbox.** Любая share-ссылка вида `https://www.dropbox.com/s/abc/file.csv?dl=0`. Флаг `dl=1` добавляется автоматически, но если он уже есть — тоже нормально.

**Прямые HTTPS-ссылки.** Любой публичный HTTPS-URL, отдающий CSV, TSV, XLSX или ZIP.

### Поведение

При первом запуске агент скачивает файл по ссылке и сохраняет его в `data/`. При повторных запусках скачивание не выполняется — используется кэш. Чтобы форсировать повторное скачивание, удалить файл из `data/`.

## Канал 2. Локальная папка

### Когда использовать

- Данные переданы файлом (по почте, мессенджеру, флешке)
- Разовая загрузка или быстрый тест
- Облачное хранилище недоступно или требует авторизации

### Как передать файл

Положить файл в папку `input/` в корне проекта:

```
readmission-risk-agents/
├── input/
│   └── dataset.csv        ← сюда
```

Имя файла роли не играет. Агент сканирует папку и выбирает **первый подходящий файл по времени изменения** (самый свежий).

Если `input/` пуста или в ней только неподдерживаемые форматы, агент завершит работу с ошибкой о недоступности источника.

## Поддерживаемые форматы

| Расширение | Поведение |
|---|---|
| `.csv` | Читается через `pandas.read_csv` с автоопределением разделителя |
| `.tsv` | Читается как CSV с табуляцией в качестве разделителя |
| `.xlsx` | Читается через `pandas.read_excel` (первый лист) |
| `.zip` | Распаковывается, внутри берётся первый CSV |

## Требования к содержимому

- Минимум 1 000 строк (для осмысленного обучения моделей)
- Минимум 5 числовых или категориальных колонок
- Одна колонка должна быть целевой — с заданным исходом (агент выберет её автоматически)
- Идентификаторы пациентов, даты, административные поля допустимы — агент исключит их перед обучением

Тестовая валидация выполнена на датасете 101 766 × 50.

## Нормализация пропусков

Перед обработкой пропуски приводятся к единому виду:

- `"?"` → `NaN`
- `"Not Available"` → `NaN`
- Пустые строки → `NaN`

Если в данных используется другой маркер пропуска (например, `-999` или `"UNK"`), его можно привести к `NaN` вручную до загрузки — либо доверить LLM на этапе EDA (агент умеет распознавать колонки с аномальными значениями).

## Приоритет каналов

Если заполнены оба канала (и `DATASET_URL`, и файл в `input/`), приоритет — у канала 1 (URL). Это позволяет избежать случайного использования устаревшего локального файла, когда в облаке лежит актуальная версия.

Чтобы переключиться на канал 2, достаточно очистить значение `DATASET_URL` в `settings.env`.

## Диагностика источника

После успешного запуска ячейки конфигурации в выводе указывается выбранный канал:

```
Settings loaded: OPENROUTER_API_KEY=set, tracing=false, data_source=URL
```

или

```
Settings loaded: OPENROUTER_API_KEY=set, tracing=false, data_source=local input/ folder
```

Если источник не найден, `ingest_data` вернёт ошибку:

```
Could not obtain dataset: No dataset source available. 
Either set DATASET_URL in config/settings.env or place a .csv/.zip/.tsv/.xlsx file into input/
```
